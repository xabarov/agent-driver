## Кандидаты (по убыванию ценности для текущих хостов)

1. **Плагинная memory-подсистема** — hermes: 8 провайдеров (mem0, honcho, supermemory, …),
   query_rewrite, prefetch с latency/budget-контрактами, fail-open recall; openclaude: memdir +
   team-memory + relevance-поиск + governance записи. *Для MeetScript это кросс-сессионная
   память «забывчивого руководителя» — прямое продолжение Аргус-бенча (персона, факты,
   предпочтения между сессиями чата).* Самый сильный кандидат в следующий большой эпик.
2. **Goal-directed continuation** — openclaude `src/services/goal/` (controller/evaluator/
   persistence, stop-hooks с goal-тестами): петля не останавливается, пока цель не достигнута.
   Родственно нашему «модель хочет искать дальше, а её обрывают»; правильная зрелая форма.
3. **Provider fallback chain + smart routing** — openclaude per-turn simple-vs-strong routing,
   rate-limit fallback-цепочки; hermes gateway-надёжность (watchdogs, circuit breakers).
   Частично входит в эпик 016 (fallback-chain); routing — отдельная тема поверх нашего
   auxiliary_model_routing.
4. **Repo-map / corpus-map intelligence** — openclaude `src/context/repoMap/` (tree-sitter +
   PageRank + кэш). Для MeetScript аналог — «карта корпуса встреч» (проекты/люди/темы) как
   штатный источник контекста чата вместо чистого retrieval. Интересно, но требует
   продуктового решения.
5. **Session branching/fork + деterministic task reports** — openclaude #1801/#1808/#1824.
   У нас checkpoint/resume есть; ветвление — следующий шаг.
6. **Self-maintaining skill library** — hermes curator/background_review (авто-архивация и
   консолидация agent-created скиллов). Актуально, когда skills-подсистема наберёт объём.
7. **MoA (mixture-of-agents) loop** — hermes: reference/advisor фан-аут с фолдингом истории.
   Дальний горизонт; наш subagents-план ближе.
8. **Verify-on-stop** — hermes verification_stop: bounded follow-up, когда модель закрывает
   задачу без свежих evidence. Перекликается с нашим evidence-gate у MeetScript — но в движке.

## Рекомендация

Ближний цикл: эпики 016-019 (надёжностные плоскости — фундамент). Следующий большой эпик —

## Аддендум 2026-07-23 — делта референсов (hermes +1001 коммитов до 6096f73ce, openclaude +22 до 01a01fb)

Свежий pull + сверка после инцидента «Сохраняю прогресс». Из инцидента родились эпики
**024** (терминальная дисциплина), **025** (статус-протокол / нет немой стадии),
**026** (conversation-first контракт хоста), **027** (гигиена recall памяти).
Темы делты, осознанно НЕ ставшие эпиками сейчас:

9. **Clarify-плоскость** — доминирующая новая тема hermes (17 коммитов): first-class тул
   `clarify` с полным лайфциклом — канонический таймаут across CLI/TUI/desktop/gateway
   (507d479c8), late-reply после таймаута, выживание через reconnect/hydration (d21165c2f),
   проза перед poll-ом, подавление tool-progress во время clarify. У нас clarify — мягкая
   промпт-политика (и это правильно по Принципу №1 MeetScript); поднимать в first-class
   interaction — продуктовое решение хоста (кнопки-варианты в UI). Отложено до запроса продукта.
10. **Turn lease / сериализация сессии** — hermes `gateway/turn_lease.py`: per-session lease
    вокруг [load history → run → flush] против интерливинга конкурентных ходов. У MeetScript
    сериализацию даёт очередь chat_jobs; станет актуально при конкурентных каналах к одной
    сессии.
11. **Stale-stream circuit breaker** — hermes `_check_stale_giveup` + пер-модельные полы
    stale-таймаутов (`agent/reasoning_timeouts.py`): повторные «застойные» стримы
    классифицируются как timeout+fallback кросс-ходово. Частично пересекается с нашей
    LlmStreamIdleTimeout; смотреть при следующем инциденте стримов.
12. **Credentials/secrets-плоскость** — hermes credential_pool/rotation, `should_rotate_credential`
    в классификаторе. Не наш deployment-профиль (один ключ через gateway), пока не нужно.
13. **Reconnect/hydration UI-состояния** (hermes 16 коммитов) — desktop/TUI-специфика,
    у MeetScript SSE-replay уже покрывает возврат на страницу.

Сверка классификатора: hermes 862b1b37b (empty-response advisories перехватываются ДО
overflow-паттернов во всех путях классификации) — наш аналог уже стоит с эпика 016
(EMPTY_RESPONSE раньше overflow); расхождений не найдено, но паттерн-таблицу
`_EMPTY_PROVIDER_RESPONSE_PATTERNS` стоит подтянуть при следующем проходе 016.

## Аддендум 2026-07-23 (2) — глубокий фиче-скан обоих референсов → эпики 028-032

Полный свип структуры/доков/гит-лога hermes (6096f73ce) и openclaude (01a01fb) с прицелом
«что даст хостам», за вычетом уже покрытого и отложенного выше. Движковые кандидаты
оформлены эпиками:

- **028 tool-plane context economy** — deferred-каталог тулов (hermes tool_search /
  openclaude ToolSearch) + 3-уровневый spill крупных tool-выводов (hermes
  tool_result_storage).
- **029 cache-safe fork-agent substrate** — openclaude forkedAgent + hermes
  async_delegation (idle-turn completion queue) + frozen-snapshot дисциплина памяти.
- **030 layered compaction plane** — openclaude compressToolHistory (stateless-шим) +
  microCompact (time-based) + contextCollapse (span-collapse форк-агентом) + hermes
  todo re-inject; смежно: per-agent doom-loop как сверка 019.
- **031 structured-output headless contract** — openclaude SyntheticOutputTool;
  контрактно закрывает класс dd9a5ee (extraction-флейки).
- **032 observability contract maturation** — hermes observer/middleware split,
  correlation-ID, санитизация payload, версии схемы (дельта к 010).

Продуктовые кандидаты (cron/suggestions-дайджесты, knowledge-graph «карта корпуса

## Аддендум №2, 2026-07-23 — capability-скан раунд 2 (hermes до 8fc278207, openclaude 01a01fb)

Вторая линза — не инцидентная, а «что полезного мы не взяли» (3 агента: hermes,
openclaude, инвентаризация своих возможностей). Родились эпики **028** (экономика
промпт-кэша — движок готов на 80%, хост не включал), **029** (пейджинг больших
тул-результатов — №1 RAG-рычаг по обоим референсам), **030** (steering v2: диспетчер
4/11 kinds + hermes redirect), **031** (фоновая консолидация памяти — hermes
background_review + openclaude auto-dream), **032** (cost-плоскость: aux-task учёт,
роллапы, LLM-титулы).

Осознанно отложено (дополнение к пп. 9-13):

14. **Durable async-делегация** (hermes `tools/async_delegation.py`): SQLite-баked
    fan-out c crash-recovery, delivery-claim протоколом и фолдингом детской стоимости —
    субстрат для «разложи вопрос по всем встречам, доставь когда готово». Отложено:
    CEO-бенч показал, что map-reduce-гипотеза пока не нужна (86/90 без неё); вернуться,
    когда появится класс вопросов, не влезающий в один ран.
15. **Cron-suggestions** (hermes `cron/suggestions.py`): consent-first предложения
    автоматизаций («еженедельный дайджест встреч») с dedup-латчем и источником
    `usage` (ревьюер заметил повторяющийся запрос). Продуктовое решение — предложить
    владельцу отдельно.
16. **Session-slot dedup** (hermes `gateway/session.py` `_SessionFlight` owner/waiter):
    конкурентные запросы одного слота делят результат владельца. Актуально при
    мульти-вкладках/каналах — сейчас очередь chat_jobs сериализует.
17. **Elicitation** (openclaude): типизированный вопрос пользователю мид-ран — родня
    clarify-плоскости (№9), та же судьба (ждёт продуктового запроса).
18. **Hook-event таксономия** (openclaude 27 событий PreToolUse…FileChanged) — готовый
    каталог extension-seams для хоста; брать по мере надобности, не оптом.
19. **Plan/permission gates c classifier-approval** (openclaude): быстрый LLM
    авто-одобряет низкорисковые действия, эскалируя неоднозначные — апгрейд нашего
    propose_meeting_reanalysis-подтверждения, когда действий станет больше одного.

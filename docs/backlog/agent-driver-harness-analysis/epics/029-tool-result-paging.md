# Пейджинг больших тул-результатов: persist + preview + дочитывание по требованию

Дата создания: 2026-07-23 (исследование референсов, раунд 2). Статус: **DONE 2026-07-23 (A,D,E; B/C отложены с причинами)**.

Мотивация: ОБА референса независимо ставят это лучшим RAG-рычагом. Наш текущий ответ на
большие тул-результаты — жёсткий чар-клип на уровне domain tools (480/900 симв. на
фрагмент, `domain_tools._truncate_text`) — молча выбрасывает содержимое встречи посреди
ответа; в движке есть только truncation аргументов и финального сообщения. Ни persist,
ни пейджинга, ни пер-ходового бюджета, ни кэш-безопасной очистки старых результатов.

## Reference-first

- **hermes `tools/tool_result_storage.py` + `budget_config.py`** — 3 слоя: (1) per-result
  порог (дефолт 100K симв., пер-тул из реестра, скейлинг от окна модели: 15% на результат,
  30% на ход, минимум 8K) → полный результат на диск, в контексте `<persisted-output>`:
  превью 1500 симв. до последнего \n + путь + инструкция «read_file(offset,limit) для
  секций»; (2) per-turn бюджет 200K — спиллит крупнейшие; (3) `read_file` pinned к inf
  (анти-цикл persist→read→persist). Реестровый кап, чтобы окно-скейлинг реально ограничивал.
- **openclaude `utils/toolResultStorage.ts`** — то же + два не-очевидных приёма:
  UTF-8-безопасное head/tail-превью с резкой по \n; **прогрессивная очистка старых
  tool_results с кэш-дисциплиной**: кандидаты делятся на mustReapply (уже заменённые —
  реплей идентичной замены ради стабильности префикса), frozen (видел провайдер,
  не заменялись — трогать нельзя, сломает кэш), fresh (можно чистить) — замена только
  fresh, крупнейшие первыми, до бюджета 200K на API-message.
- Пустой результат → явный маркер «(tool completed with no output)» — модель не
  завершает ход на голом метаданном хвосте (оба референса).

## Эскиз фаз

A. **Движок, persist-слой**: `ToolResultStore` протокол (host-pluggable: файл/Mongo) +
   per-result порог в реестре тулов + `<persisted-output>`-конверт (превью по \n, ключ
   результата, инструкция дочитывания). Встроенный тул `read_tool_result(key, offset,
   limit)` (pinned-неперсистимый). Пустой результат → маркер.
B. **Per-turn бюджет** + окно-скейлинг порогов (доли окна как у hermes; переиспользовать
   резолв окна эпика 017).
C. **Кэш-безопасная прогрессивная очистка** (openclaude frozen/mustReapply) в
   protocol_messages при росте мультиходовой сессии — согласовано с 028 (не ломать
   префикс) и 018 (pair-integrity).
D. **Хост MeetScript**: retrieval-тулы (get_meeting_fragments/search_*) переходят с
   жёстких чар-клипов на persist+preview; ключ результата = (meeting_id, диапазон
   фрагментов) — «дочитать» реализуется уже существующим get_meeting_fragments, store
   может быть тонким. Приёмка: вопрос по длинной встрече, где ответ лежит ЗА текущим
   чар-клипом (сегодня — потерян молча), начинает отвечаться.
E. Приёмка: бенч-свип без регрессий + новый кейс «глубокий факт за клипом»; замер
   среднего инпут-токенажа хода до/после на coverage-классе.

## Не в скоупе

Кэш-маркеры (028), реранжирование retrieval (хостовая политика).

## Дополнение 2026-07-23 (раунд 2b)

- **hermes 3-слойная защита** (`tools/tool_result_storage.py`): (1) само-обрезка per-tool;
  (2) `maybe_persist_tool_result` — большой результат в файл песочницы с
  `<persisted-output>`-превью + путь + «read_file offset/limit»; (3) `enforce_turn_budget` —
  агрегатный бюджет хода 200K чаров, спилл САМЫХ КРУПНЫХ результатов первыми. Превью
  режется по границе строки; запись через stdin-pipe обходит MAX_ARG_STRLEN 128K.
- **UTF-8-safe обрезка** — у openclaude это повторяющийся класс багов (grapheme-boundary
  фиксы a6b3d7a, b588c26, 7b9e477): для RU-текста рез по байтам посреди кириллицы =
  мусор в превью. Обрезку делать по кодпойнтам/строкам, с точным маркером
  «omitted N bytes» (buildLargeToolResultMessage).
- **Хост-фаза: подача retrieval** (hermes `session_search_tool.py` — почти готовый шаблон
  для Ask Meetings): сниппет матча + окно ±5 сообщений + bookend'ы (первые/последние 3
  хода встречи) для ориентации модели; **демоция источников** — повторяющиеся
  низкосигнальные встречи (стендапы) демотируются в BM25, не исключаются («recall
  blindness» hermes #19434); компакченные сессии остаются находимыми.

## Отложено с причинами (фазы B, C)

- **B** per-turn бюджет 200K + окно-скейлинг порогов — крупная движковая машинерия
  агрегатного бюджета хода; для одноходового RAG-чата (наш профиль) низкий ROI.
- **C** кэш-безопасная прогрессивная очистка (frozen/mustReapply) — глубоко трогает
  multi-turn protocol_messages и пересекается с кэш-маркерами эпика 028; брать вместе
  с агентными многоходовыми сценариями, не раньше.
Триггер разблокировки: агентная многоходовая сессия с накоплением крупных тул-выводов.

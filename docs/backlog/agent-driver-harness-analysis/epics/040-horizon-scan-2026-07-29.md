# Horizon scan 2026-07-29: дельта референсов после сканов 2026-07-23

Дата создания: 2026-07-29. Статус: **proposed** (кандидаты в эпики 041-044 + фазы-обновления).

Дельта: hermes `8fc278207..e0233f8fc` (+2103 коммита, ~60% voice/desktop/платформенные
адаптеры — исключены), openclaude `01a01fb..ae634cd` (+22, все прочитаны).

## Главный сигнал: конвергенция на liveness

Оба референса в одну неделю независимо инвестировали в одну идею: **stall-детекция по
прогрессу, а не по wall-clock**. Openclaude `c23b6e1`: heartbeat-обёртка вокруг всего
tool-вызова (30s synthetic progress, merge последнего серверного прогресса, инвалидация
кэша прогресса на retry/elicitation, форвардинг детского прогресса родителю, ephemeral —
не в транскрипт). Hermes: thread-local `aux_progress_hook` в `auxiliary_client` (стрим
принудительно, таймаут = per-chunk idle, потолок `max(600s, 4×task_timeout)`) +
progress-token staleness для делегатов (`api_call_count + current_tool + last_activity_ts`;
stalling 450s idle / 1200s in-tool → interrupt → 120s grace → terminal `stalled` со
структурированным контекстом). Контрпример там же: hermes `cfb206fe2` (wall-clock
watchdog) **отреверчен** `2c1809e6c` — выжил именно liveness-подход.

## Кандидаты в новые эпики

### 041 — liveness/progress plane (топ-кандидат)
Прогресс-сигнал как первоклассный контракт рантайма: (a) heartbeat-обёртка тулов —
молчаливый тул отличим от мёртвого; (b) aux-вызовы (компакция, грейдеры) стримом с
idle-таймаутом вместо wall-clock бюджета (мотивация hermes: 30s дедлайн убивал медленные
но здоровые модели → 300s cooldown → сессия остаётся oversized → doom loop); (c) stall-
детекция subagent'ов по progress-token с grace-периодом и терминальным `stalled`-событием
(смежно 034). Источники: openclaude `c23b6e1`; hermes `32fd9d65c`, `99a381f31`, `5f5afb1ee`.

### 042 — tool-call wire integrity
Правило: **никогда не синтезировать завершённость tool-call'а**. (a) openclaude `2fe1e1b`:
стрим оборвался без terminal reason при in-flight tool call → hard fail (не «дочинить
JSON»); repair усечённых аргументов только при провайдерском terminal reason; при
`finish_reason=length` буфер сохраняется, но не исполняется. (b) hermes `63954d508`:
`finish_reason="tool_calls"` с ПУСТЫМ массивом tool_calls (Copilot/opus-4.8) → петля
принимала нарратив за финальный ответ, unattended-джоб «успешен» при `tool_turns=0`;
фикс — bounded re-prompt (3 подряд, сброс после успешного раунда). (c) hermes `474c84ed8`:
провайдер переиспользует `tool_call_id` в одном батче → второй результат молча исчезал
из реплея; фикс — детерминированный ресуффикс `<id>_d<n>` при инжесте (кэш-стабильный).
Расширяет 016/018, но это отдельная плоскость: отказ от достройки неполноты.

### 043 — transcript-poisoning hygiene (CoT never persisted + один владелец repair)
Hermes `cf0c42fa0` — самый ценный коммит дельты: `/steer` во время thinking-фазы
сериализовал streamed reasoning в персистентный чекпоинт ассистента → выглядит как
prefill/reasoning-injection → **каждый последующий вызов сессии возвращает empty,
навсегда** (4 сессии окирпичены, 42+ вызовов; ни один recovery-бранч не спасает, т.к.
отравлен персистентный префикс). Правила: (a) streamed CoT — display-only, никогда в
history; (b) «пустой non-final turn» чинится ОДНИМ владельцем в pre-send chokepoint
(hermes удалил 4 форкнутые реализации, оставил `repair_empty_non_final_messages` в
`sanitize_api_messages`); (c) каждое синтетическое сообщение несёт scaffolding-тег,
который чтят одновременно persistence, compaction и display projection (hermes
`923704c7c`: nudge-пара без тега реплеилась как user-authored контекст); (d) в ладдер 016
добавить детекцию «unescapable poisoned prefix». Обновляет 016/018/030 сразу — потому
отдельный эпик.

### 044 — context-engine seam: select_context / on_turn_complete
Hermes `agent/context_engine.py` (ABC): к lifecycle добавлены **`select_context()`** —
каждый ход, после сборки request, до dispatch: подменить состав ЭТОГО промпта
(retrieval, topic routing, ветки) **без мутации персистентной истории** — и
**`on_turn_complete(transcript, usage)`** — пост-ходовая индексация для следующего
select. Оба fail-open (включая ловушку `all([]) is True`). Плюс `context_breakdown.py`:
оценка состава следующего запроса по категориям (system/tools/skills/memory/conversation)
**той же эвристикой, что и порог компакции** — UI-число и триггер согласованы (`/context`).
Для RAG-хостов (MeetScript, excel-ai) это штатный шов вместо злоупотребления
`should_compress()`. Расширяет 017/035 новой поверхностью.

### 045 — event-driven wait: park-on-event вместо поллинга (добавлен 2026-07-30)
Примитив `wait_for_event`: подписка на внешнее событие (exit процесса, файл/inotify,
webhook, очередь) → checkpoint → освобождение петли → wake с payload'ом события новым
ходом. Фундамент готов: `contracts/durable_lifecycle.py` (durable-статусы, lease'ы,
resume/fork-вердикты) + checkpoint/resume; сегодня wake только от человека (approval),
interrupt'а или time-driven `Scheduler`-тика — модель, ждущая внешний процесс, вынуждена
tool-поллить (и per-turn капы 019 её за это накажут). Четыре требования: (1) примитив +
новый lifecycle-переход; (2) liveness-бэкстоп на каждую подписку — hook, который не
выстрелил, деградирует в bounded-poll/`stalled`, НЕ висит (= фаза 041, идут вместе);
(3) delivery-claim гарантия доставки через crash (чертёж — hermes `async_delegation`,
отложенный №14); (4) промпт-правило «долгое внешнее ожидание → подписка, не поллинг».
Бонус: припаркованный ран не мутирует префикс — дружит с 028. Дешёвый тест: event-source
«exit фонового процесса» поверх shell-тула, ось `eval compare --treatment event_wait`,
baseline-поллинг vs park; на DS V4 Flash ~$5-10 за свип; продуктовая примерка потом —
MeetScript jobworker (notify вместо поллинга статуса job'а).

## Обновления существующих эпиков (фазы, не новые эпики)

  overflow (`207a6c969` — format_error, не compress!); `"throttling"` в rate-limit раньше
  `"too many tokens"`; litellm/Bedrock-конверт `{errorMessage, errorCode, errorArgs}`;
  `gateway_auth_failed` ≠ provider 401. Урок: overflow — «attractive nuisance», его
  recovery (compress) деструктивен, всё спорное упорядочивать раньше. Плюс hermes
  `backend_identity.py` (`39b596556`): три оси failure-scope — credential / endpoint /
  model-deployment; unknown → MODEL (наименее инвалидирующий). Шесть колл-сайтов, семь
  инцидентов до выделения — брать готовым.
- **019**: (a) hermes `cb06017b1` — капы per-turn, не per-session (`loop_caps`, 50/ход),
  при этом глобальный iteration limit 90→500: дешёвые пер-тульные капы вместо глобального
  потолка как doom-loop guard; (b) openclaude `9d5b77d` — параллельный fan-out N
  одинаковых ошибок инкрементит счётчик ОДИН раз за ход: порог меряет «ходы без
  адаптации», а не события.
- **033**: hermes tiered disclosure (`0986ac393`): tier 0 eager / tier 1 листинг в бюджете
  (деградация per-server, largest-first, детерминированно → cache-safe) / tier 2 только
  `tool_search` + однострочные сводки серверов (Cloudflare: 3320 тулов, 597K схем;
  измеренный failure mode tier 2 — подмена core-тулом и «нет такой возможности»). Плюс
  blind-call schema probe (`8fbe2e388`): deferred-тул вызван без required-аргументов →
  вернуть схему вместо слепого dispatch (дешёвые модели крутили ~30 идентичных
  невалидных вызовов до смерти бюджета) — прямо бьёт по нашим open-weight прогонам.
- **028**: конкретные триггеры инвалидации префикса: redecorate breakpoints после
  failover; реконструкция static prefix на restore и после компакции; breakpoints ПОСЛЕ
  нормализации сообщений; `proactive_prune_min_reclaim_tokens` (гистерезис: prune
  коммитится только если отбивает ≥4096 токенов — иначе ломает кэш каждую итерацию);
  no-op контракт «skip возвращает входной объект, коммит только при `result is not messages`».
- **018**: методология conformance vectors (hermes `29fc74635`): замороженные векторы
  вывода адаптеров, стемпленные коммитом оракула, багфикс = новый вектор. Дёшево, прямо
  ложится на наши provider-адаптеры.
- **035**: ghost-skill защита (`5faef80a4`+): канонический `[SKILL_PRUNED]`-маркер,
  переживающий компакцию — модель не должна «помнить» выгруженный skill/док/файл.
  Обобщается на любые крупные эфемерные тела в контексте.
- **037/010**: openclaude `c23b6e1` — инварианты fault containment для host-обзерверов:
  бросивший `started/progress/completed/failed`-консюмер не меняет исход тула и не роняет
  процесс (отдельно: timer-коллбеки сбегают из try/finally); по тесту на инвариант.

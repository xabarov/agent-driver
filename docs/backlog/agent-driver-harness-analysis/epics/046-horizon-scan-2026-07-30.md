## Кандидаты (по убыванию ценности для движка)

### 1. SQLite durability hardening (hermes #2) — HIGH, реальный gap у нас — ✅ DONE 2026-07-30

> Реализация: `persistence.open_sqlite_connection` (единый opener, stdlib-only) —
> `busy_timeout` (default 30s, write-lock patience) + `journal_mode=WAL` с проверкой
> фактически возвращённого значения (silent WAL→DELETE на NFS/overlay → WARN, либо
> `WalUnsupportedError` при `require_wal`). Все 3 сайта проведены: `SqliteStoreBase`
> (sessions/artifacts/context/plan/record) + `subagents/store.py` + `subagents/mailbox.py`
> (последние два были без WAL и без busy_timeout вовсе). 6 тестов; свип 2857 passed.

hermes ~8 коммитов (`8da8a7887`, `f50d80e8e`, `0f60cdac2`, `556784600`, `91351b7b7`,
`04ec84146`) закалили SQLite-стор турнов против мульти-процесса и враждебной ФС:
- **Time-based write-lock patience** (не attempt-count): старый бюджет (~1.3s) сдавался,
  пока сиблинг легитимно держал БД секундами (VACUUM после prune, TRUNCATE-checkpoint на
  close, mixed-version при rolling-update) → `append_message` фейлился и **абортил
  здоровый ход** («session_persistence_failed»). Прод: 10.8GB БД, 9 процессов.
- **Silent WAL→DELETE детекция**: на NFS/SMB/overlay `PRAGMA journal_mode=WAL` возвращает
  `'delete'` без исключения → БД молча в reader-blocks-writer режиме, ноль сигнала.
  Фикс читает возвращённую строку, эскалирует WARN→ERROR, опц. `require_wal`.
- **Transient vs deterministic disk-I/O**: «disk i/o error» ретраится (backoff), не
  даунгрейдит БД с WAL-заголовком.
- **Единый `journal_mode` + централизация всех openers** (5 bypass-путей в один WAL-путь).

**Наш статус — GAP подтверждён:** 3 несцентрализованных `sqlite3.connect` (`persistence/
sqlite.py`, `subagents/store.py`, `subagents/mailbox.py`); WAL включён ТОЛЬКО в
`persistence/sqlite.py`; `busy_timeout`/write-lock-patience — **нигде**; WAL-fallback
детекции нет. Урок load-bearing: **storage-contention timeout не должен абортить здоровый
ход**, а деградация concurrency **не должна быть немой**. Доменно-нейтрально, прямо
применимо. → эпик/фаза: централизовать opener (WAL + busy_timeout + patience + fallback-
детекция), провести все 3 сайта через него.

### 2. Amortized per-turn micro-compaction (hermes #1) — высшая ценность, но кэш-враждебно
hermes ~14 коммитов (доминирующая agent-runtime тема; `186cad02f` intro, `d19c18287`
default-off, `9ca4ee72c` cadence-knob, `ac48add3a` occupancy-телеметрия). Вместо одного
крупного batch-стойла при заполнении окна — `finalize_turn` в пост-ходовый idle сворачивает
самый старый неабсорбированный ход в накопительное summary (курсор от последнего маркера,
protected head/tail verbatim, defrag при пороге). Расширяет 035/028 **новой дисциплиной
расписания** (амортизация стоимости компакции по ходам вместо стойла).

**Ключевой caveat (их же урок, драйвивший реверс в default-off):** micro-pass переписывает
уже отправленную историю → **ломает кэш-префикс КАЖДЫЙ ход**, а не на эпизодической
границе. `micro_compact_every_n_turns` явно фреймит «как часто гоняем» = «как часто платим
кэш-брейк». Прямая коллизия с нашей 028 (prompt-cache economics). Телеметрия: «tokens
saved» — неверный заголовок (работа та же), мерить надо **occupancy** (`after/threshold`).
Плюс каталог грабель: курсор от post-splice индекса, summary-маркер assistant-роль,
batch/micro маркеры разделять, rehydrate на resume. → кандидат эпик **047**, но default-off
и с A/B occupancy vs cache-hit-rate; решать, стоит ли овчинка при нашем cache-first профиле.

### 3. Fail-loud name collisions + provenance header (hermes #5) — SMALL, портабельно
Из org-skill governance (продуктовая обёртка Nous — пропустить), портабельные примитивы
для нашего tool/skill-registry: (a) коллизия bare-name помечает **ОБА** входа
`[name collision — load via category path]` — никто молча не выигрывает (personal-wins =
немой дивергенс, org-wins = затенённая работа); (b) provenance-заголовок при загрузке с
edit-policy; (c) entitlement-gated видимость с offline-grace + инвалидация по snapshot-hash.
→ фаза к registry/skills: fail-loud коллизии вместо тихого precedence.

## Осознанно отложено / watching

- **Credential-pool generation-guard (openclaude #1)**: monotonic `generation` на лизе
  против ABA-гонки (stale in-flight success не чистит свежий cooldown; auth-eviction
  оверрайдит generation). Чистый концаренси-примитив, НО наш `HealthAwareRouter` проще
  (health+fallback, не leased-пул с cooldown под фан-аутом) → взять, ЕСЛИ добавим
  cooldown-pooling кредов. Watching.
- **Isolation soft-fallback degradation contract (openclaude #2)**: когда запрошенная
  isolation-гарантия недостижима — деградировать, но пробросить downgrade как (a)
  структурный флаг в sync+async result-схемах, (b) notice модели, (c) notice юзеру + fail-
  closed валидация spawn-параметров + resume-durable execution root. Обёрнуто в worktree
  (отложенный). Паттерн портабелен, если добавим capability-gated spawn-деградацию. Watching.
- **Live steer running delegated worker (hermes #3)**: out-of-band watermarked note-channel
  в живого делегата без рестарта (030+034). Наши сабагенты bounded/awaited, не
  long-running interactive → продуктовое, отложено.
- **MCP clean-shutdown/parked-task drain (hermes #4)**: reap parked-startup тасков перед
  close (owner для сервера, зафейлившего до регистрации). MCP-специфично, низкая
  генеральность; сверить при следующем инциденте MCP-teardown.

## Кандидат #1 — hermes micro-compaction = наш отложенный B2, реализованный + закалённый — HIGH

hermes построил и за неделю закалил ровно тот **amortized per-turn micro-compaction**,
который скан 046 пометил «высшая ценность, но кэш-враждебно» и отложил. Это и есть наш
отложенный **compaction-эпик B2 (amortized/rolling summary)** — уже реализованный в
референсе, с решёнными сложными местами.

### Механизм (hermes)
Складывает **один exchange за завершённый ход** в кумулятивную rolling-summary вместо
одной большой батч-суммаризации при заполнении окна. Курсор `_micro_compact_cursor`
метит первый непоглощённый message; каждый проход = `rolling_summary + один новый
exchange` → один мелкий aux-LLM вызов (merge-промпт) → обновлённая summary; поглощённый
спан вырезается и заменяется одним assistant-маркером с `_compressed_summary`-метаданными.
Голова (system) и токен-хвост неприкосновенны. User-ходы НИКОГДА не поглощаются.

### Закалка (каждый урок = баг, который он предотвращает)
- **Курсор из spliced-list** — иначе pre-splice индекс перелетает (splice схлопывает ~4+
  msg в 1 маркер) и садится внутрь tool-группы → пол-работы молча пропускается (tool-free
  фикстуры не ловят).
- **Alternation-safe маркер (assistant-role, exchange по границам user)** — иначе
  `user→user→user`, и `repair_message_sequence` сливает маркер в реальный user → метаданные
  потеряны, summary дублируется в транскрипт каждый ход (транскрипт РАСТЁТ).
- **Defrag сохраняет user-ходы** — иначе первый дефраг сериализует весь middle (с user) и
  вырезает → 8/10 user-промптов уничтожены за проход.
- **Resume-safety** — rolling summary только в памяти; resumed сессия стартует пустой,
  первый проход суперсидит full-history маркер → тотальная потеря. Фикс: регидрат summary
  из маркера + гейт суперсида на непустую summary.
- **Разделение batch/micro маркеров** (distinct `MICRO_COMPACT_MARKER_KEY`) — иначе micro
  supersede/defrag дропает батч-маркер, чьего контента в stale rolling summary нет →
  durable-потеря.
- **Гейт против duck-typed компрессоров** (`is True` + callable + non-empty) — иначе mock's
  truthy auto-attr вызывает `_micro_compact` на моке, splice пустого возврата стирает всё.
- **Poison-exchange guard** — после 3 фейлов на курсоре пропустить и сдвинуть.

### Ручки + cost/cache-трейдофф
opt-in (default OFF), `micro_compact_every_n_turns` (cadence — единственный рычаг числа
cache-брейков), defrag-threshold (2000 tok), **выбор модели = главная ручка** (мелкая
instruct, не reasoning). Честный вердикт самих доков: per-turn переписывание истории
**ломает prompt-cache-префикс каждый ход** — это ТРЕЙД, не экономия; на провайдере с
глубокой cache-скидкой может стоить дороже устранённого стойла. «Меряй свои сессии.»

### Телеметрия occupancy (`ac48add3a`, `cac9526d2`)
«tokens saved» — неверный заголовок (та же работа). Реальный выигрыш: стойло
амортизировано + occupancy плоский вместо пилы к порогу. Per-pass JSON:
`occupancy_pct = tokens_after / compaction_threshold` (из КЭШИРОВАННОГО порога, без
блокирующего `/models`-пробе), + threshold/limit/exchange/summary токены/duration/тоталы.

## Вердикт: адоптировать как реализацию B2 — с архитектурным упрощением в НАШУ пользу

hermes micro-compaction **и есть** B2. Ключевая разница в нашу пользу: hermes мутирует
in-memory список + синхронит session-DB (`archive_and_compact`, resume-double-load — целый
класс багов, за который они заплатили). У нас уже есть **immutable-log (`protocol_messages`)
/ ephemeral-View (`request.messages`)** split → rolling summary = **кэш-артефакт по префиксу
лога**, БЕЗ их DB-sync/resume-машинерии. Самый рискованный кусок их арки нам не нужен.

**Портировать (по value×effort):**
1. Rolling-summary cursor + fold-one-slice (ядро B2) — High/Med; у нас это prefix-keyed
   cache-update, не in-place DB-splice → проще hermes.
2. **Occupancy-телеметрия** — High/Low; **СТЕНДАЛОН, делать первым** — меряет, спит ли
   плоскость (наш gating-вопрос: excel-ai держит compaction OFF, и даже ON дормант на SSB),
   и переориентирует «успех» с tokens-saved.
3. Opt-in default + cadence config — High/Low; обязательно для наших prompt-cache-хостов.
4. Разделение batch/micro маркеров — Med-High/Low.
5. Cursor-from-spliced-list — Med/Low (портировать УРОК, не код, если B2 = offset-по-префиксу).
6. Full-turn/user-preserving + «user-ходы не суммаризируем» — Med/Low (инвариант принять).
7. Duck-typed/disabled гейт — Low-Med/Low.
- **ПРОПУСТИТЬ:** `archive_and_compact` DB-sync + resume-rehydrate — решают проблему, которой
  у нашей immutable-log/View модели НЕТ.

**Cost/cache — приемлемо ТОЛЬКО opt-in + cadence.** Per-turn cache-брейк реален (наш
ephemeral-View его НЕ спасает — провайдер всё равно видит изменённый префикс). НО: плоскость
дормант при малом `trim_max_chars` → на таких хостах брейка просто нет; на больших-бюджет
хостах ~12.5k-tok/step экономия — ровно там выигрыш. Оставить наши circuit-breaker +
idle-timeout (hermes их не имеет).
